## Public-data HotpotQA pilot

For a small model-backed evaluation on public examples, obtain the official [HotpotQA dev distractor file](https://curtis.ml.cmu.edu/datasets/hotpot/hotpot_dev_distractor_v1.json) locally (about 44 MB; dataset page and license details are on the [HotpotQA homepage](https://hotpotqa.github.io/)). The dataset is licensed CC BY-SA 4.0. The harness reads the local JSON path you provide and does not download or vendor the dataset. The official CMU URL is the default source attribution. If the local file came from a mirror, pass its public HTTPS source URL so the benchmark names the actual source. For example, the available [Hugging Face mirror](https://huggingface.co/datasets/namlh2004/hotpotqa) file is about 61 MB; its local SHA-256 identifies those exact bytes and differs from the CMU file checksum even though the first three sampled records were validated against the official Hugging Face dataset:

```powershell
python -m bytevox_harness hotpotqa-compare `
  --dataset-path .\runs\public-data\hotpot_dev_distractor_v1.json `
  --source-url https://huggingface.co/datasets/namlh2004/hotpotqa `
  --sample-size 3 --provider openai-compatible `
  --base-url $env:BYTEVOX_BASE_URL --model $env:BYTEVOX_MODEL
```

`--source-url` defaults to the official CMU dataset file URL, accepts a public HTTPS URL without embedded credentials, query, or fragment, and is stored with the exact local file hash. Keep downloaded data under `runs/public-data/`; this folder is ignored by Git and must not enter the submission.

The default sample size is three: without `--sample-seed`, it selects the first `comparison` example and first `bridge` example, then fills remaining slots in source order; a one-example sample uses the first source record. Supply `--sample-seed 42` to choose a reproducible proportional stratified sample by question type. Both selection rules and source indices are recorded in the benchmark provenance.

For a fresh holdout, pass `--exclude-ids-file` with a UTF-8 newline-delimited list of previously evaluated HotpotQA `_id` values. Exclusions are applied before stratified allocation; the report records the exclusion count and hash, selected IDs, source indices, and dataset/corpus hashes. `--max-aggregate-cost-usd` optionally checks the planned count of task/mode/repeat runs multiplied by `--max-cost-usd` before the first run. Both are estimate guards based on configured rates, not provider billing guarantees.

Each context sentence becomes a separate evidence item. A precomputed sparse BM25 index uses Unicode-aware tokenization, stopword filtering that retains short entity terms such as `Ed`, `US`, and `AI`, and a title-field boost; complete titles remain searchable even when a filename slug is shortened. Before planning, the lead receives the top five results for the raw question as untrusted `seed_evidence`. The prompt asks it to use discovered entity names to form direct or dependent follow-up specialist queries. A valid specialist query is searched by itself to preserve the planner's distinct retrieval intent; only a missing or invalid query falls back to the raw question plus the specialist's goal. The full task remains in each worker model payload, and the task-specific goal drives worker focus. Each specialist can retrieve at most five sentences, while the single-agent baseline can retrieve up to fifteen.

The harness receives the raw question, evidence, and a generic task contract. The trusted contract requires the first summary line to begin `Answer: ` and contain at most eight words after that prefix; it is meant for the answer phrase alone (for example, `Answer: January 1930`). The rule does not contaminate retrieval queries. Gold answers and supporting facts stay in scorer records and are evaluated only after each run has finished. Both modes receive the same question and contract. A missing, malformed, or overlong answer line is flagged by harness validation and may receive zero answer EM/F1 under the post-run parser. In addition to cited supporting-fact precision/recall/F1, the post-run scorer reports retrieval support recall from completed `search_documents` results in the closed JSONL trace; this separates retrieval misses from citation-selection misses.

The scorer maps cited sentence IDs back to HotpotQA `(title, sent_id)` references and reports normalized answer EM/F1, supporting-fact precision/recall/F1 and exact match, retrieval support recall, plus joint answer/support EM/F1. The formulas and normalization follow the [official HotpotQA evaluator](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py). Results are written to `runs/hotpotqa-benchmark.md`, `.csv`, and `.json`, separate from the fixture comparison files; the reports include provider response format, source file and corpus hashes, split, version, license, sample rule, run links, latency, known token use, and known API cost. Repeated paired runs also include a deterministic two-level bootstrap: task IDs are resampled with replacement, then matched repetition indices are resampled within each selected task so multi/single scores remain paired.

### D45 query/evidence handoff and controlled HotpotQA A/B

D45 removes the full-question append from valid specialist searches while retaining the raw-question top-five lead seed. A missing or invalid planner query uses the task-anchored fallback. Workers keep the original task, specialist goal/focus/query, evidence, and untrusted-data notice; planner assignments are scope/search hints, never instructions. Worker payloads omit the validation contract. ### D47 caller-supplied answer-prefix normalization

The D45 traces showed caller-required `Answer: ` prefixes missing from otherwise answer-bearing summaries. The harness now inserts or canonicalizes only that trusted first-line prefix before coverage checks or the multi-agent checker; it records `answer_format_normalized` and leaves claims and evidence IDs untouched. The existing word limit and evidence checks still run, and planner/fallback contracts are excluded. A 10-example public HotpotQA holdout triggered the normalizer on four candidate runs; all four remained reviewable and completed. The one-repeat code-off/code-on comparison had 19/20 completed runs in each variant and mixed metric changes, so it provides no quality-gain evidence. ### D48 planner-seed evidence handoff

The v7 `hotpotqa-0027` trace showed a raw-question seed record with the Tamaulipas-to-Ciudad-Victoria relation was absent from all worker result lists and therefore absent from synthesis, even though retrieval scoring counted it. D48 passes the existing planner seed records into the shared synthesis pool, deduplicates by evidence ID, records the lead as a source, bounds excerpts, and reserves one novel seed hit within the same eight-record cap. The checker still reviews citations against source text. The full local suite passes 51 tests, including new coverage for the handoff, provenance, truncation, and cap behavior. This is an evidence-availability fix; no remote run or answer-quality result has been measured for it. See the [decision record](decision.md#d48--carry-a-novel-planner-seed-into-synthesis) and [execution flow](flow.md#d48-carry-a-novel-planner-seed-into-synthesis).
For a code-side remote spending guard, set `--max-cost-usd` or `BYTEVOX_MAX_COST_USD` and both per-million-token rate variables to the endpoint's current prices. A requested remote cap is rejected before any provider request if either rate is missing or invalid. This is an **estimated USD cap**, not a guaranteed billing limit: before each request, the harness reserves estimated prompt cost plus maximum completion cost from token counts, then reconciles reported usage after a successful response. If reported usage exceeds its estimate, the run is marked partial for review and later requests are checked against the higher reported spend; parallel requests already in flight may also finish. If a request fails or usage is omitted, its reservation stays committed conservatively and may block later requests. The estimate applies to each provider-backed task/mode run: default `compare` has six, and `demo` has the same six plus offline safety examples. `compare --repeats N` has `6 × N` provider-backed runs. Set a matching provider-side hard spend limit as an additional safeguard; this generic adapter cannot configure the provider's billing controls.


### D49 D48 model-backed evaluation

A fresh 10-example HotpotQA holdout ran the D48 candidate and a pre-D48 control on the same IDs, corpora, model, prompts, and budgets. The D48 batch completed 20/20 runs; the control completed 19/20. Candidate multi-agent joint F1 was 0.4494 versus 0.4460 for the control, a paired delta of +0.0034 (95% bootstrap interval −0.0467 to +0.0637). One planner-only gold support sentence reached synthesis but was not cited, so the evidence path is verified while a quality gain is not.
